## What this is

A fully installable PWA for tennis coach Martina Gledacheva — court-side CRM and lesson planner. Clients, notes, and sessions are persisted locally in IndexedDB. Lesson plans are generated by Google Gemini 2.0 Flash. Sessions can be booked into Google Calendar via OAuth. Data can be backed up and restored via Google Drive.

The `prototype/` directory contains the original Babel/CDN design prototype (no build tooling); it is reference-only and not part of the PWA build.

## Architecture

### Router (no library)

`src/App.tsx` owns all navigation state:
- `route: { name: RouteName, params: Record<string, string> }` — current screen
- `tab: TabName` — active bottom tab (`today | roster | settings`)
- `sheet: SheetName` — active bottom sheet overlay (`schedule | note | confirm | null`)

Route names: `today`, `roster`, `profile`, `addClient`, `editClient`, `lessonConfig`, `lessonLoading`, `lessonOutput`, `settings`. Profile/lesson routes carry `params.id` (client ID). The `editClient` route renders `AddClientScreen` with `initialClient` pre-filled. Screens are chosen via a `switch` on `route.name`; sheets layer on top as portaled overlays.

### State (Zustand)

Single store in `src/store/index.ts` with six slices — never split across multiple stores:

| Slice | Key state |
|---|---|
| `ClientsSlice` | `clients[]`, `clientsById` map |
| `NotesSlice` | `notesByClient: Record<clientId, Note[]>` |
| `SettingsSlice` | `settings: Settings \| null` |
| `AuthSlice` | `googleToken`, `googleTokenExpiry`, `googleEmail` |
| `GenSlice` | `genConfig`, `genPhases`, `genSource`, `genStage` |
| `CalendarSlice` | `todaySlots: CalendarSlot[]` |

Store is never persisted to localStorage — all durable data lives in IndexedDB (Dexie). The store is a read-through cache that `App.tsx` populates on mount via `loadData()`.

### Persistence (Dexie / IndexedDB)

`src/services/db.ts` exports `db` (a `TennisDB` Dexie instance) and `seedIfEmpty()`.

Tables: `clients`, `notes`, `lessons`, `settings` (singleton row with `id: 'singleton'`).

`seedIfEmpty()` is called once on app mount; it inserts 8 seed clients + 18 seed notes + the default settings row only if the `clients` table is empty. Seed data lives in `src/data/seed.ts`.

### Lesson AI (`src/services/lessonAi.ts`)

Calls Gemini 2.0 Flash directly (`generativelanguage.googleapis.com`) with structured JSON output (no SDK). Key behaviour:
- No API key → immediate `fromFallback()` return
- HTTP 400/403 with API-key-related message → auto-clears the key from settings, returns fallback
- HTTP 429 → one 1.5 s retry, then fallback
- Malformed JSON → one retry, then fallback
- `AbortError` is re-thrown (caller handles it for back-nav cancellation)

`fromFallback(focus, duration)` builds a 4-phase plan from `src/data/drills.ts` using the first focus area and `durationSplit()`.

`LessonLoadingScreen` drives `generate()` alongside a 700 ms interval timer that advances a 5-step stage display independently of actual AI progress.

### Google Drive (`src/services/drive.ts`)

Separate GIS token client using `drive.file` scope — completely independent of the Calendar token. The access token lives in-memory only (`_driveToken`), never persisted, expires in ~1 hour.

**localStorage keys** (prefix `tennis_`):

| Key | Contents |
|---|---|
| `tennis_drive_email` | Connected Google account email; presence = Drive connected |
| `tennis_drive_root_id` | Drive folder ID for `TennisCoach/` root folder |
| `tennis_drive_sync_file_id` | Drive file ID for `tennis-coach-sync.json` |

These keys are safe to sync (they're not secrets). `geminiApiKey` is explicitly excluded from push/pull sync and is never written to Drive.

**Sync payload** (`tennis-coach-sync.json` in `TennisCoach/`): all rows from the `clients`, `notes`, `lessons`, and `settings` Dexie tables — with `geminiApiKey` stripped from settings. On pull, the local `geminiApiKey` is preserved and merged back into the restored settings row.

**Folder structure**: a single `TennisCoach/` folder at Drive root; no subfolders (no binary files to store). `_driveEnsureFolders()` is idempotent — find-or-create on first use per session, cached in localStorage thereafter.

**Public API**: `driveIsConnected()`, `driveGetEmail()`, `driveConnect()`, `driveDisconnect()`, `drivePushSync()`, `drivePullSync()`.

**Requirements**: Google Drive API must be enabled in the Google Cloud Console project that owns `VITE_GOOGLE_CLIENT_ID`.

### Google Calendar (`src/services/calendar.ts`, `src/services/googleAuth.ts`)

GIS (Google Identity Services) token client flow — **not** OAuth redirect. `requestToken()` opens the GIS popup and stores the short-lived access token in the Zustand `AuthSlice`. `ensureToken()` silently refreshes (prompt: `''`) if the token is expired.

`createEvent()` posts to `/calendars/primary/events`. `listDay()` fetches all events for a date and fuzzy-matches event summaries against the `clients` store to populate `clientId`.

### Design system

All CSS is in `src/styles.css` (global, no CSS modules). Key tokens:
- `--clay` / `--clay-tint` / `--clay-deep` — terracotta brand accent (#C0432A)
- `--ink` / `--ink-3` / `--ink-4` / `--ink-5` — text hierarchy
- `--surface` / `--surface-2` — cream backgrounds
- `--line` — subtle borders
- `--font-display` — Instrument Serif (italic for phase names)
- `--font-mono` — Geist Mono (timings, NTRP values)

Screens mix CSS classes with inline styles. Add new screens the same way — no styled-components, no Tailwind.

### PWA

`vite-plugin-pwa` with `generateSW` mode and `autoUpdate` registration. Base URL is `/tennis/` (serves from `jharari.github.io/tennis`). Icons live in `public/icons/`. Gemini API responses are **not** cached by the service worker.

### CI/CD

`.github/workflows/deploy.yml` builds on push to `main` and deploys `dist/` to GitHub Pages. Set `VITE_GOOGLE_CLIENT_ID` as a repository **variable** (not a secret) in GitHub → Settings → Variables → Actions.

## Key conventions

- All TypeScript types are centralised in `src/types.ts`. Do not define domain types inline.
- `src/components/ui/index.ts` is the barrel for all shared UI primitives — import from there, not individual files.
- The `LessonPhase` card colour sequence is `surface-2 → ink → clay → surface-2` (cycling). The `PHASE_STYLES` array in `LessonOutput.tsx` defines this — do not reorder.
- All lessons are **60 minutes**. Duration is hardcoded to `60` everywhere — there is no selector in `LessonConfig`, `ScheduleSheet`, or Settings. Do not add duration selectors or a `defaultDuration` UI.
- Duration splits (warm-up / technical / tactical / finish minutes) are derived from `durationSplit()` in `src/lib/split.ts`, always called with `60`.
- `src/vite-env.d.ts` must keep both `/// <reference types="vite/client" />` and `/// <reference types="vite-plugin-pwa/client" />` for `import.meta.env` and `virtual:pwa-register` to resolve correctly.

## Client data model

The `Client` interface (in `src/types.ts`) uses:

- **`ntrp?: number | null`** — skill level on the USTA 1.0–7.0 scale. This is the sole skill indicator; there is no separate "Level" field. `archetypeId` is derived from player type + NTRP (see `AddClient.tsx`).
- **`hasRacket?: boolean`** — whether the client brings their own racket (`true`) or the coach provides one (`false`).
- **`ballType?: BallType`** — one of `'red' | 'orange' | 'green' | 'yellow'`. Red = foam/beginner, orange = low compression, green = green dot transition, yellow = standard.
- There is no `gear` string field. Do not reintroduce it.

The `AddClientScreen` (`src/screens/AddClient.tsx`) uses:
- A **Type** chip selector (Adult / Junior / Group) to set the player category.
- An **NTRP slider** (range 1.0–7.0, step 0.5) with a live description. Hidden for Group clients. `archetypeId` is auto-derived: adult ≤ 2.5 → `adult-beg`, ≤ 4.0 → `adult-int`, > 4.0 → `adult-adv`.
- **Own racket?** Yes / No chips → `hasRacket`.
- **Ball type** chips → `ballType`.

## iOS PWA install

The `IosInstallHint` component (bottom of `src/screens/Settings.tsx`) renders a step-by-step install guide only when `navigator.userAgent` matches iPhone/iPad/iPod and the app is not already running in standalone mode. Do not show it on Android or desktop.

## Client deletion

`ProfileScreen` (`src/screens/Profile.tsx`) has a trash icon in the AppBar trailing slot (alongside the calendar icon). Tapping it shows an inline bottom sheet confirmation that deletes the client + all their notes + lessons from IndexedDB via a Dexie transaction, updates the Zustand `ClientsSlice`, then calls `onDelete()` to navigate back to the Roster.
