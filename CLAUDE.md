# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A fully installable PWA for tennis coach Martina Gledacheva — court-side CRM and lesson planner. Clients, notes, and sessions are persisted locally in IndexedDB. Lesson plans are generated by Google Gemini 2.0 Flash. Sessions can be booked into Google Calendar via OAuth.

The `prototype/` directory contains the original Babel/CDN design prototype (no build tooling); it is reference-only and not part of the PWA build.

## Commands

```bash
npm run dev       # Vite dev server at http://localhost:5173/tennis/
npm run build     # tsc && vite build → dist/
npm run preview   # Serve dist/ at http://localhost:4173/tennis/
```

There are no tests. Validation is visual — run the app and inspect.

## Environment variables

Copy `.env.local.example` → `.env.local`:

```
VITE_GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com
```

Without this, Google Calendar integration is disabled but the app runs fully in offline/fallback mode.

## Architecture

### Router (no library)

`src/App.tsx` owns all navigation state:
- `route: { name: RouteName, params: Record<string, string> }` — current screen
- `tab: TabName` — active bottom tab (`today | roster | settings`)
- `sheet: SheetName` — active bottom sheet overlay (`schedule | note | confirm | null`)

Route names: `today`, `roster`, `profile`, `addClient`, `lessonConfig`, `lessonLoading`, `lessonOutput`, `settings`. Profile/lesson routes carry `params.id` (client ID). Screens are chosen via a `switch` on `route.name`; sheets layer on top as portaled overlays.

### State (Zustand)

Single store in `src/store/index.ts` with six slices — never split across multiple stores:

| Slice | Key state |
|---|---|
| `ClientsSlice` | `clients[]`, `clientsById` map |
| `NotesSlice` | `notesByClient: Record<clientId, Note[]>` |
| `SettingsSlice` | `settings: Settings \| null` |
| `AuthSlice` | `googleToken`, `googleTokenExpiry`, `googleEmail` |
| `GenSlice` | `genConfig`, `genPhases`, `genSource`, `genStage` |
| `CalendarSlice` | `todaySlots: CalendarSlot[]` |

Store is never persisted to localStorage — all durable data lives in IndexedDB (Dexie). The store is a read-through cache that `App.tsx` populates on mount via `loadData()`.

### Persistence (Dexie / IndexedDB)

`src/services/db.ts` exports `db` (a `TennisDB` Dexie instance) and `seedIfEmpty()`.

Tables: `clients`, `notes`, `lessons`, `settings` (singleton row with `id: 'singleton'`).

`seedIfEmpty()` is called once on app mount; it inserts 8 seed clients + 18 seed notes + the default settings row only if the `clients` table is empty. Seed data lives in `src/data/seed.ts`.

### Lesson AI (`src/services/lessonAi.ts`)

Calls Gemini 2.0 Flash directly (`generativelanguage.googleapis.com`) with structured JSON output (no SDK). Key behaviour:
- No API key → immediate `fromFallback()` return
- HTTP 400/403 with API-key-related message → auto-clears the key from settings, returns fallback
- HTTP 429 → one 1.5 s retry, then fallback
- Malformed JSON → one retry, then fallback
- `AbortError` is re-thrown (caller handles it for back-nav cancellation)

`fromFallback(focus, duration)` builds a 4-phase plan from `src/data/drills.ts` using the first focus area and `durationSplit()`.

`LessonLoadingScreen` drives `generate()` alongside a 700 ms interval timer that advances a 5-step stage display independently of actual AI progress.

### Google Calendar (`src/services/calendar.ts`, `src/services/googleAuth.ts`)

GIS (Google Identity Services) token client flow — **not** OAuth redirect. `requestToken()` opens the GIS popup and stores the short-lived access token in the Zustand `AuthSlice`. `ensureToken()` silently refreshes (prompt: `''`) if the token is expired.

`createEvent()` posts to `/calendars/primary/events`. `listDay()` fetches all events for a date and fuzzy-matches event summaries against the `clients` store to populate `clientId`.

### Design system

All CSS is in `src/styles.css` (global, no CSS modules). Key tokens:
- `--clay` / `--clay-tint` / `--clay-deep` — terracotta brand accent (#C0432A)
- `--ink` / `--ink-3` / `--ink-4` / `--ink-5` — text hierarchy
- `--surface` / `--surface-2` — cream backgrounds
- `--line` — subtle borders
- `--font-display` — Instrument Serif (italic for phase names)
- `--font-mono` — Geist Mono (timings, NTRP values)

Screens mix CSS classes with inline styles. Add new screens the same way — no styled-components, no Tailwind.

### PWA

`vite-plugin-pwa` with `generateSW` mode and `autoUpdate` registration. Base URL is `/tennis/` (serves from `jharari.github.io/tennis`). Icons live in `public/icons/`. Gemini API responses are **not** cached by the service worker.

### CI/CD

`.github/workflows/deploy.yml` builds on push to `main` and deploys `dist/` to GitHub Pages. Set `VITE_GOOGLE_CLIENT_ID` as a repository **variable** (not a secret) in GitHub → Settings → Variables → Actions.

## Key conventions

- All TypeScript types are centralised in `src/types.ts`. Do not define domain types inline.
- `src/components/ui/index.ts` is the barrel for all shared UI primitives — import from there, not individual files.
- The `LessonPhase` card colour sequence is `surface-2 → ink → clay → surface-2` (cycling). The `PHASE_STYLES` array in `LessonOutput.tsx` defines this — do not reorder.
- Duration splits (warm-up / technical / tactical / finish minutes) are always derived from `durationSplit()` in `src/lib/split.ts`, never hardcoded.
- `src/vite-env.d.ts` must keep both `/// <reference types="vite/client" />` and `/// <reference types="vite-plugin-pwa/client" />` for `import.meta.env` and `virtual:pwa-register` to resolve correctly.
